# AegisAI 継続的セキュリティ更新手順

状態 **レビュー用ドラフト** · 2026-11-25 JST  
配置候補 `LuCIA-Trustworks-LLC/.Global-Strategy/security/SECURITY-UPDATE-PROCESS.md`

AegisAI は、責任ある AI を運用できるセキュリティ環境を継続的に改善し、企業が自社のリスクと責任範囲に合わせて導入・検証できる形で提供する。Kernel は実行時の認可を担う。この更新手順は、認可に加えて、主体・開発環境・クラウド・データ・監査・インシデント対応を対象とする。

既存の `SECURITY.md` は最低限の統制と報告経路、`FRAMEWORK-MAP.md` は参照元とマッピング、`AGENTS.md` は AI の作業境界を定める。本手順では、それらを見直し、変更を承認し、実効性を確認する流れを定義する。

## 1. 変更の受付と判断

- **受付** — 担当者は、基準の版変更、クラウドや依存関係の変更、監査の指摘、インシデント、新しい利用形態を変更候補として登録する。出所、版、公開日、取得日、資料の状態（正式・ドラフト・社内案）、関係する統制 ID を記録する。
- **影響評価** — 影響を受ける企業・システム・データ・主体を特定する。現行の統制と差分を確認し、適用の要否、優先度、暫定対策、責任者、確認期限を記録する。
- **レビュー** — 対応案は既存の PR 経路で審査する。提案者と承認者を分け、影響、検証条件、復旧方法を確認する。AI は差分要約と下書きを支援し、承認と適用の判断は指定責任者が行う。
- **効果確認** — 対象環境で許可される操作と拒否される操作を別々に確認する。テストの環境・設定版・実施日・結果・証拠 ID を記録する。
- **引き渡しと再評価** — 承認済みの統制と検証方法を企業向け導入票に反映する。未評価・計画・実装済み・実効性検証済みの状態を記録し、期限付き例外は期限前に再評価する。

月次の参照資料レビューと、重大な変更が判明した際の随時評価を初期案とする。実際の担当・頻度・エスカレーション期限は運用責任者が決定する。

## 2. 初期の優先対象

| 優先 | 対象 | 企業で示す証拠 |
|---|---|---|
| P0 | Agent のアクセス範囲と人間・サービス主体の分離 | ロール、ファイル隔離の許可／拒否結果、レビュー履歴 |
| P0 | データ出口、秘密の供給、クラウドとの責任分界 | 値を伏せた設定、宛先ルール、実施済み検証の証拠 ID |
| P0 | セキュリティ設定の変更、監査、障害対応 | 承認者、適用記録、拒否記録、復旧確認 |
| P1 | 依存関係、モデル・ツール追加、AI 利用範囲の変化 | 台帳、更新前後の差分、再検証の対象と結果 |

## 3. 企業向け導入票

| 項目 | 記入内容 |
|---|---|
| 統制 | ID、名称、適用版、判断根拠 |
| 範囲 | 対象システム、利用目的、データ分類 |
| 責任分担 | 利用企業、クラウド事業者、運用委託先ごとの実施者・承認者 |
| 実施 | 必要な設定、実施順、前提条件、復旧手順 |
| 検証 | 許可・拒否の合格条件、実施日、状態、内部証拠 ID |
| 例外 | 理由、残存リスク、代替策、承認者、失効日、次回レビュー |

公開用の導入票には、承認済みの統制の説明と検証方法を掲載する。運用証拠、顧客データ、認証設定、未修正の脆弱性情報は企業の承認した保管先で管理する。

## 4. 参照資料の扱い

- **NIST AI RMF 1.0** — GOVERN、MAP、MEASURE、MANAGE を責任分担・適用範囲・検証・改善の見直しに使用する。[NIST AI 100-1](https://doi.org/10.6028/NIST.AI.100-1)
- **NIST Cyber AI Profile の Spring 2026 COI 議論資料** — AI に関わるサイバーリスクの優先付けを検討する資料。正式採用候補は発行元の版と状態を確認して記録する。
- **CSA CCM / CAIQ v4.1** — クラウド統制と、サービス提供者・利用企業の責任分担を確認する参照資料。既存 Framework Map の適用承認条件に従う。[CSA CCM / CAIQ v4.1](https://cloudsecurityalliance.org/artifacts/cloud-controls-matrix-v4-1)
- **AegisAI Implementation Profile v0.1-draft** — 既存の組織内評価を初期入力に使用する。実効性は対象環境の証拠で確認する。

マッピング、組織内評価、実効性確認は別の状態として記録する。企業向けの文書には証拠と承認範囲に沿った表現を使用する。
